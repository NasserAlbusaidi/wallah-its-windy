## E — Pin static replay-critical asset bytes in CI

Not in the audit; found during review. Nothing currently pins the *values* of
the baked assets. `test/integration-bins.test.ts:110-190` asserts presence,
bounds, `nt >= 3`, and plane diversity — never values. A one-LSB quantization
flip from a re-bake would be silent, and CLAUDE.md's determinism contract
promises shared URLs replay byte-identically.

**Review correction:** the draft pinned only `env.bin` planes. That is
insufficient. `terrain.bin` drives land decay and impact land classification,
`ocean.bin` feeds coupled OHC diagnostics, and the event bins drive scenario
URLs — all replay-critical.

**Review correction — "full replay-critical asset set" is not an executable
rule.** `scenarios.json` can reroute the same URL to different data even when
every event-bin byte is unchanged, so a hand-picked list will rot.

Deliverable: a SHA-256 manifest over every **static replay asset** in
`public/data/`, asserted in CI. A directory rule rather than a curated list, so
a newly baked static asset is covered the day it lands instead of the day
someone remembers to add it. The manifest is generated by script and committed;
CI recomputes and diffs. New static files appearing without a manifest update
fail the gate — that is the point.

Two namespaces are deliberately excluded by prefix:

- `live/` is regenerated by `npm run live:acquire` before `npm test` in the
  scheduled deployment workflow. Its manifest contains `generatedAt` and its
  partial environment changes with each source cycle. Comparing those bytes
  with a committed static manifest would fail every successful acquisition.
- `satellite/` is an observation cache, not deterministic replay forcing. Its
  frames and provider manifest may change independently of simulator URLs.

Those exclusions are part of the executable contract and are themselves
tested. Live-cycle integrity remains enforced by `public_cycle.py`'s
content-addressed archive and manifest validation; observed satellite integrity
remains enforced by its provider/frame manifest. Excluding volatile
observations does not exempt any static `.bin` or scenario catalogue that
affects deterministic replay.

Three constraints the rule needs to survive contact:

- The manifest file lives **outside** `public/data/`, or it hashes itself.
- Traversal is **recursive**, so a future subdirectory is not silently skipped.
- Entries are ordered by **canonical relative path with forward slashes**, so
  the manifest is byte-identical on Windows and Linux. This repo is developed on
  Windows and gated in Linux CI; a platform-dependent manifest would fail the
  gate on every push for reasons unrelated to the data.
- The CLI entry-point comparison uses `pathToFileURL(resolve(process.argv[1]))`;
  hand-assembled `file://` URLs are not equivalent on Windows.
- Drift detection is exercised with synthetic manifest maps. It never modifies
  a tracked data file and never uses `git checkout --` as a test cleanup step.

Must exist before any bake change.

## A — Three shipped defects

No sealed metric records any of these values. Verified: no file under
`calibration/` consumes `impact.ts`; no sealed JSON carries
`initializationTier` or `missingSourceFlag`.

That does **not** mean A3 is invisible to sealed reproducibility. Its
implementation changes `src/sim.ts` and `src/upper-ocean.ts`, and HF-4/HF-6
hash those runtime sources in their verification artefacts. A3 therefore
requires a controlled reproduction-artifact refresh after the numeric checks
prove unchanged output: regenerate HF-4 and HF-6 verification through their
scripts, regenerate the matching acceptance artefacts, and require the diff to
contain source/verification hashes only. Every metric, threshold, cohort,
scorecard value, and rejected verdict remains byte-identical. This is the same
two-artifact reproducibility repair documented by P0.7; it is not retuning or a
new scientific look at the cohort.

HF-6 also hashes `hf4-acceptance.json`, so its acceptance manifest changes both
`verificationSha256` and `hf4Sha256` after the HF-4 refresh. That transitive hash
is expected; no HF-4 or HF-6 scientific result changes.

### A1 — The CDO and cirrus canopy get their own scale

**Defect.** `structure.ts` deliberately contracts RMW as the storm intensifies
(bounded Willoughby–Rahn proxy). `src/render/env.ts:536` passes only
`structure.rmwKm / 666` as `u_rMax`, and every canopy feature is a multiple of
it. A strengthening storm therefore has a correctly contracting eyewall and an
incorrectly contracting cloud shield, even while `outerSizeKm` grows.

**Design.** New pure module `src/render/storm-radii.ts`:

```ts
export interface StormRenderRadii {
  /** Inner core, clip units. Eye, eyewall, vortex wind, rainband envelopes. */
  rMax: number;
  /** Canopy scale, clip units. CDO, cirrus, canopy offset, noise space. */
  rCanopy: number;
}
export function stormRenderRadii(structure: StormStructure): StormRenderRadii;
```

**Review correction — the monotonicity guard was itself the bug.** The draft
defined `rCanopy = max(outerDerived, rMax)` as an inversion guard.
`structure.ts:89-90,106-107` clamps `rmwKm ∈ [12, 95]` and
`outerSizeKm ∈ [60, 420]`; the ranges overlap, so `rmwKm > outerSizeKm` is
reachable. Wherever that floor binds, `rCanopy` collapses to `rMax` and resumes
contracting with the inner core — reintroducing the defect precisely in the
regime the guard was written to protect.

The guard is therefore removed. `rCanopy` is a function of `outerSizeKm`
**alone**, monotone non-decreasing in it, with a constant numerical floor
(not an `rMax`-derived one). A weak storm whose RMW exceeds its outer radius is
a real state — a broad ragged core — and the renderer should depict it, not
clamp it away.

**Review correction — the formula was missing.** "Monotone in `outerSizeKm`
with a constant floor" is not a specification; the actual conversion and the
re-derived coefficients decide whether the eye can clear more area than the CDO
occupies at the extreme reachable state (`outerSizeKm = 60`, `rmwKm = 95`).
Specified now:

```
rCanopy = max(RENDER_RADIUS_FLOOR, outerSizeKm / HALF_DOMAIN_HEIGHT_KM)
```

with `HALF_DOMAIN_HEIGHT_KM = 666` (the existing divisor) and
`RENDER_RADIUS_FLOOR = 0.008` (the constant already guarding `u_rMax` at
`env.ts:110` and `radar.ts:48`). Strictly proportional to `outerSizeKm`, so
monotonicity is proven by construction rather than asserted, and independence
from `rmwKm` is structural rather than tested-for.

Canopy coefficients are divided by the reference ratio
`outerSizeKm / rmwKm = 180 / 40 = 4.5`, so the reference render is unchanged:

| Feature | Old (× `rMax`) | New (× `rCanopy`) |
|---|---|---|
| `coreRadius` (CDO) | 2.25 → 3.55 | 0.5 → 0.78889 |
| cirrus scale | 5.8 | 1.28889 |
| canopy shear offset | 0.82 | 0.18222 |

**Write these in code as exact quotients (`2.25 / 4.5`), not as the rounded
values shown here.** The table is for reading; rounding it into a shader is how
a reference regression drifts on day one.

At the extreme state (`outerSizeKm = 60`, `rmwKm = 95`): `rCanopy = 0.0901`,
`rMax = 0.1426`, so the CDO spans **0.045 → 0.071** while the eye reaches
**~0.066**. The eye can exceed the CDO. That is a real morphology for a broad
weak storm, but it must be *seen* before it is accepted: the reference
regression test is joined by a rendered check at both clamp corners.

**Per-expression mapping.** Every `rMax` use in `env.ts` resolves as:

| Expression | Line | Moves to `rCanopy`? |
|---|---|---|
| `q = length(radial) / rMax` (eye, eyewall) | 111 | no — inner core |
| canopy shear displacement `rMax * shearN * 0.82` | 119 | **yes** |
| `canopyQ = length(canopyRadial) / rMax` | 120 | **split** (see below) |
| `spiralSpace = canopyRadial / rMax` (noise space) | 129 | **yes** |
| `canopyDir = canopyRadial / (canopyQ * rMax)` | 192 | **yes**, both terms consistently |
| central overcast, cirrus | 160, 204 | **yes** |
| rainband envelope | 163-164 | **no** — see A2 |
| eye radius | 209 | no — inner core |
| Holland wind mode `pow(rMax / r, hollandB)` | 348 | no — surface-wind physics |

**Review correction — the band phase terms had no assigned coordinate.**
`bandPhase` (`env.ts:166`) and `secondaryBand` (`:168-172`) both descend from
`canopyQ`, and the draft's two-way split left them unassigned. Worse, a naive
split tears the bands: as intensity rises the `rMax` envelope narrows while a
growing `rCanopy` coarsens the noise, so large cells get clipped by a shrinking
annulus and band pitch stops agreeing with band extent.

Three named coordinates, and every consumer is assigned one:

| Coordinate | Definition | Drives |
|---|---|---|
| `coreQ` | `\|radial\| / rMax` | eye, eyewall, Holland wind mode |
| `bandQ` | `\|canopyRadial\| / rMax` | band envelope **and band phase pitch** |
| `canopyQ` | `\|canopyRadial\| / rCanopy` | central overcast, cirrus |
| `textureSpace` | `canopyRadial / rCanopy` | `macro`, `fine`, `cirrusTexture` |

The tearing is avoided by putting band *pitch* on `bandQ` alongside band
*extent*: the deterministic terms of `bandPhase` and `secondaryBand` (azimuth
and radial pitch) use `bandQ`, so position and pitch always agree. Only the
stochastic offset — the `macro`/`fine` contribution that makes bands ragged —
comes from canopy-space noise. One noise field, no extra sample on the mobile
tier, and the only canopy-scaled property of a band is its irregularity.

This asymmetry is deliberate and is the part most likely to be "corrected" by a
future reader: `textureSpace` is canopy-scaled because cloud granularity
contracting with the inner core is one of the original defects; band position is
core-scaled because it must match the three rain products (A2).

Required regardless: rendered QA at both clamp corners before merge. This is
the one part of A1 a unit test cannot cover.

Shader multiples (`coreRadius` 2.25–3.55, cirrus `/5.8`, canopy offset 0.82) are
re-derived so that at a reference structure (`rmwKm ≈ 40`, `outerSizeKm ≈ 180`)
the render is unchanged. This is a decoupling, not a resize.

Authoritative radii and coefficient arithmetic live in TypeScript and are
interpolated into the GLSL template, so the tested constants cannot drift from
duplicated shader literals. Rendered QA still covers the plumbing that a unit
test cannot see.

**Tests, written first.**
- Monotonicity over **reachable** structure states from the clamp ranges above,
  including `rmwKm > outerSizeKm`: `rCanopy` is non-decreasing in `outerSizeKm`
  and **independent of** `rmwKm`.
- Reference-structure regression pinning today's effective radii.
- Rendered QA at both clamp corners (`60/95` and `420/12`), reviewed by eye.

**Scope boundary — A1 does not fully fix the shrinkage, and must not claim to.**
Because the band envelope stays on `rMax` (A2), the *band component* of the
cloud shield still contracts as the storm intensifies. A1 stops the central
dense overcast, the cirrus canopy, the canopy offset, and the cloud texture from
shrinking. It does not stop the bands. The audit's remedy asked for independently
bounded outer cloud **and** rainband radii; this delivers the first half. The
second half is gated behind an area-normalized rain-footprint model with a
validation target (A2), because moving band extent without it silently inflates
accumulated rainfall. Ship the partial fix, state the boundary in the layer
documentation, and do not describe A1 as a cloud-shield fix.

### A2 — One rainband contract

**Defect.** Three consumers, two azimuthal means, 26% apart:
`render/radar.ts:53` `max(0.08, 0.54 + 0.46·sin)` → mean 0.54;
`render/rain.ts:153` `0.68 + 0.32·sin` → mean 0.68;
`impact.ts:258` fixed `0.68`.

**Review correction — the draft's remedy inflated rainfall.** The draft moved
all four consumers' band envelopes to `rCanopy` and described the result as a
"wider, lower-peak footprint". That is false. The envelope maximum,
`rainbandRainMmH`, and the 0.68 factor are all unchanged by a radial rescale,
so the **peak rate is identical and integrated rain grows with footprint area**
(`impact.ts:237-249`). Nothing in the design conserved total rain. It would
have silently inflated accumulated city rain, point-probe rain, flood tiers,
narrative output, and the hydro source footprint — an unvalidated QPF change
riding along with a display fix, which no existing test would catch.

**Design.** Fix the stated defect and nothing else. New
`src/rainband-profile.ts` owns the shared contract:

- `RAINBAND_AZIMUTHAL_MEAN = 0.68` — the value two of three consumers already
  use, and the one the ledger deposits.
- Shared arm geometry: three arms with radial pitch 1.35. Radar additionally
  uses the existing 0.035-radian-per-sim-hour rotation; the land/wadi
  accumulator has no age uniform and evaluates the same geometry at phase zero.
- **Four** envelope transition edges, anchored to `impact.ts:251-252`:
  inner ramp `1.45 → 2.0`, outer ramp `6.0 → 8.0`. (Review correction: the draft
  named only two, which under-specifies a double-smoothstep envelope.)
- Eyewall width `0.38`, anchored to `impact.ts:249`. This resolves a three-way
  discrepancy found in review — `radar.ts:51` uses inner 1.4 and width 0.34.

**The shared contract binds the three rain products only: `radar.ts`,
`rain.ts`, `impact.ts`.** `radar.ts` adopts the shared spiral (0.54 → 0.68) and
the shared edges. All three stay normalized by `rMax`, so they remain mutually
consistent and no recorded output moves.

**Review correction — `env.ts` is deliberately outside the contract.** Its band
is a *cloud* feature, not a rain product: it keeps its development-dependent
outer radius (`6.35 → 8.8`, `env.ts:162`) and its organization-dependent eyewall
width (`0.46 → 0.27`, `:161`). Both are cloud morphology and neither is removed.
`env.ts` therefore does not import `rainband-profile.ts`. Stated explicitly
because "one rainband contract" reads as though it should cover all four
consumers, and a future reader would otherwise wire it up and flatten cloud
morphology into rain geometry.

**2026-07-28 amendment — minimum precipitating-cloud support.** The
`env.ts` no-import boundary above is deliberately relaxed: simulated IR now
shares the instantaneous rain centre, radial envelope, and spiral constants
needed to provide minimum cloud support over modeled rain. The original
morphology boundary remains in force. Its CDO, cirrus, canopy scale, texture
space, and decorative morphology bands stay independent rather than being
flattened into quantitative rain geometry.

The shared displacement calculation is renderer-only: `render/env.ts`,
`render/radar.ts`, and the render-side land/wadi rain accumulator use
`rainCenterClip`. The recorded impact ledger in `impact.ts` retains its existing
flat displacement calculation because changing it would move recorded output;
that path is outside this amendment.

**Review correction — two coordinates, not one substitution.** `rain.ts` feeds
`u_rMax` into `vortexWind`, which drives orographic rain. Consumers need
`qCore = r / rMax` for eyewall and vortex alongside any band coordinate; a
blanket substitution would corrupt rain physics.

Known limitation shipped and documented: rainband *extent* still scales with
the inner core. Correcting that requires an area-normalized rain-footprint
model with an explicit validation target — separate scoped work, not bundled
here. The shared mean is **internally consistent, not validated**, and the docs
must say so.

**Tests.** Table-driven: all consumers resolve to one mean, shared arm
geometry is pinned, and a numerically integrated mean of the spiral function
equals the documented constant, so the comment can never drift from the maths
again. Integral constants are formatted with a decimal point when interpolated
into GLSL.

### A3 — Provenance derived from the sample

**Defect.** `sim.ts:1036` assigns `initializationTier` inside the background
callback, before `deps.oceanProfileSampler` (line 1041) has been shown to return
anything. `upper-ocean.ts:985` derives `missingSourceFlag` from that tier, so a
missing `ocean.bin` yields `climatological-subsurface` + `missingSourceFlag:
false` while the column is an analytic fabrication from `profileFromSstAndOhc`.
Diagnostics and exports can claim a WOA23-initialized subsurface column that
does not exist.

**Review correction — deriving in `createColumn` cannot work.** The draft moved
tier derivation into `SparseUpperOcean.createColumn`. That can infer
"profile absent ⇒ `analytic-fallback`", but `OceanProfile` is untagged, so it
cannot distinguish `event-analysis` from `climatological-subsurface`. A present
climatological profile in an event run would be falsely labelled
`event-analysis` — a new provenance bug replacing the old one.

**Design.** Tag at the source. The tier travels with the data that justifies it:

```ts
export interface OceanProfileSample {
  profile: OceanProfile;
  tier: 'event-analysis' | 'climatological-subsurface';
  sourceValidTime?: string;
}
export type OceanProfileSampler =
  (lat: number, lon: number, monthIndex: number) => OceanProfileSample | null;
```

`null` means no profile, which is the **only** state from which
`analytic-fallback` may be inferred. `createColumn` downgrades on `null` and
clears any claimed source-valid time, fixing every caller at once.
`product-identity.ts` gains a visible degraded-data indication rather than the
state living only in exports.

**Review correction — this change is source-breaking, and several callers are
untyped.** TypeScript protects the runtime pass-throughs, but not the
calibration `.mjs` runners. Most runners coalesce and pass the sample through,
so the tagged shape remains correct without a source edit;
`hf2a-ocean-reference.mjs` directly builds an ocean background and would keep
reading a bare profile unless migrated by hand. Every untyped path is therefore
inventoried and its check rerun; HF-2A's numeric result must not move.

Tests cover all three branches explicitly: event profile present, climatological
profile present, profile absent.

`test/physics.test.ts:201` currently asserts `climatological-subsurface` while
constructing the engine with **no** `oceanProfileSampler` (`:182-186`) — it
encodes the bug. It flips, with a comment recording why.

`calibration/hf2a-ocean-reference.mjs:490-522` has the same latent pattern: the
tier is chosen from the presence of event metadata, then event and climatological
sampling are coalesced with `??`. If the event lookup misses and climatology
succeeds, it still claims `event-analysis`.

**Review correction — "verify" is not a remedy.** The coalescing must
explicitly propagate one selected tagged sample from the branch that actually
returned data, the same rule as the runtime sampler. The profile, tier, and
source-valid time all come from that selected object; an event metadata record
must not donate its timestamp to a climatological fallback. With the committed
bins the event lookups succeed, so the HF-2A numeric output should not move —
but that is the thing to confirm, not to assume.

The source-breaking caller inventory is:

- typed pass-throughs: `main.ts`, `ensemble.worker.ts`, `ensemble.ts`,
  `hindcast-benchmark.ts`, and `sim.ts`;
- untyped runners: `calibration/fidelity.mjs`, `hf2a-ocean-reference.mjs`,
  `hf4-verify.mjs`, and `hf6-verify.mjs`;
- direct shape assertions: `test/ocean-profile-sampler.test.ts`.

Every direct consumer is migrated or explicitly verified. In particular, the
profile-sampler test unwraps `.profile` and asserts the returned tier rather
than continuing to assume a bare `OceanProfile`.

## C1 — Upper-level sidecar bin

`bake/era5.py:184-185` keeps only `V200 − V850`, discarding the absolute
200-hPa field that `fetch_era5.py:36` already requests. Retaining `u200`/`v200`
unlocks an honest upper-level outflow product and a second shear layer pair.

**Delivered as a sidecar `.bin`, not as new `env.bin` layers.** Layers are
name-addressed and `layerCount` is a `u8` (56 of 255 used), so additive layers
would need no `FORMAT_VERSION` bump — but `data/raw` is git-ignored and absent
from the working copy, and `bake.py:82-140` has no append mode; it recomputes
all 56 layers. Rebuilding risks silent plane drift against the URL-replay
contract. A sidecar leaves `env.bin` untouched, following the precedent set when
steering went into its own bin so frozen env bins were not mutated
(`BINARY-FORMATS.md:281`).

**Review correction — the sidecar needs a plane-alignment contract.** The
selected ERA5 years are computed during the bake and printed, never persisted.
Nothing would stop sidecar plane N carrying a different year than committed
`env.bin` plane N — a silent desync between two files the sampler reads
together. Required: persist month/plane/year metadata alongside the sidecar,
and require the existing `u/v/shu/shv` planes to reconstruct against the pinned
`env.bin` bytes before the sidecar is accepted.

Also required: document the sidecar's layer names, quantization, and `nt`
semantics in `BINARY-FORMATS.md`, and parse it only through `src/loader.ts`.

Cost: ~106 KB (14 layers × 7 768 B at `nt = 4`).

Note for consumers: a missing layer does not throw. `env-sampler.ts:56-62`
returns null and the runtime silently substitutes the analytic climatology —
the trap CLAUDE.md already documents. Any new month-suffixed layer needs
integration-test coverage.

## C2 — New phase, not an HF-2 promotion

Emanuel potential intensity and a real Tang–Emanuel ventilation replace the
SST-based DeMaria–Kaplan proxy at `sim.ts:316`. `mpiKt` feeds the intensity ODE
for **both** physics profiles (`sim.ts:462-467`), so the blast radius is every
replay, `calibrate:check`, every HF gate, and four machine-generated reports.

**Review correction — the draft's governance framing was a violation.** It said
"HF-2 promotion requires passing its frozen gate." That gate is spent and
rejected permanently (`ROADMAP.md:46`, `findings-hf1-hf6.md:54,195-196`), and
Emanuel PI is not even the HF-2 candidate — HF-2 tested the
vector-ventilation/dynamic-ocean profile that already exists. This is new
physics and therefore necessarily a new phase.

**Review correction — replacement breaks legacy replay.** Replacing `mpiKt`
globally would alter every previously shared URL and every frozen runner that
imports it. C2 adds a **new, explicitly selected physics profile** and new gate
artefacts; the existing implementation is retained for legacy URLs and
historical checks. Rejected gates keep executing the old version and stay
byte-stable. They are never resealed.

**Review correction — the acquisition is not scoped.** C1 supplies only
absolute 200-hPa wind. The current acquisition has winds at 200/250/500/850 hPa
and RH at 600/700 hPa only — no atmospheric temperature profile, no moisture
across the declared levels, no surface thermodynamic state. "Predeclare the
level set" is not an implementation task; a genuine PI needs near-full-column
T/q and a new CDS request. Without it the result is another proxy wearing
Emanuel's name.

Legitimate path: new frozen contract written **before** any evaluation →
development-partition storms only → a **newly sealed** confirmation cohort (the
HF-6 cohort is spent, `ROADMAP.md:416`) → new gate runner → reseal only the
replay baselines, through the documented flows, with zero verdict edits.
HF-2's rejection stays frozen and visible.

`SHEAR_THRESHOLD_MS` keeps its distribution anchor as long as `shr` is
untouched, but it is a member of the joint hindcast search vector
(`sim.ts:199-210`) balancing against the MPI term, so it re-enters scope.

## D — Radiance feasibility spike

**Review correction — the blocker was misattributed twice.** It is not the
providers (my first draft), and INSAT is not fully wired (my second). Meteosat
is a EUMETView WMS **stylized 8-bit PNG** (`satellite-observations.ts:169-185`)
which cannot be inverted to brightness temperature; INSAT has no live browser
acquisition path at all — missing frames terminate with "registered MOSDAC
ingest required". The frame contract carries provider, product, and
`channel: 'infrared' | 'visible'`, with **zero radiometric metadata**, and the
manifest parser rejects any version but 1.

Calibrated L1 products do exist from both wired providers behind registration
(EUMETSAT Data Store SEVIRI L1.5; MOSDAC INSAT-3D `3DIMG` L1B/L1C with BT
lookup tables). What blocks quantitative brightness temperature is engineering:
a non-WMS acquisition path, an HDF/native decoder in the bake, a v2 manifest
with a backward-compatible parser and expanded channel/calibration types, and a
quantitative renderer.

Microwave remains genuinely provider-blocked — the wired geostationary imagers
have IR/VIS/WV and no microwave sounder.

Scope as a feasibility spike before committing to a design.

## Product-honesty commitments

Every item above ships with its label intact. The shared rainband mean is
internally consistent, not validated. Rainband extent scaling with the inner
core remains a documented limitation until an area-normalized model is built
and validated. Ventilation stays diagnostic-only until a new phase promotes it.
Ensemble output remains perturbation frequency, never probability.
